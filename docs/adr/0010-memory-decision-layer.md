## 1. Контекст и проблема

В ходе разработки и эмпирического тестирования подсистем памяти PAD+ AI (фазы `D'-1` — `D'-5` и 7 последовательных исследовательских экспериментов) было обнаружено фундаментальное ограничение:

> **Storage ≠ Retrieval ≠ Memory**

Существующий `ConversationWorkspace` и семантический `Retrieval` обеспечивают идеальную персистентность сессий и высокий `Recall@K` (до 100%), однако базовый поиск возвращает весь накопленный пул кандидатов без фильтрации дистракторов, устаревших версий и конфликтов (`False Recall Rate ~ 40%`). 

Исследование показало, что память определяется не объемом сохраненной информации и не скоростью поиска, а **механизмом выбора информации, которая имеет право участвовать в текущем когнитивном контексте**.

---

## 2. Подтвержденные и неподтвержденные гипотезы

### Подтверждено экспериментально:
- `ConversationWorkspace` обеспечивает надежную персистентность, изоляцию сессий и сохранение хронологии (`Temporal Validity`).
- Базовый семантический поиск справляется с базами до 1500+ записей с латентностью < 7 мс (`MRR = 1.0`).
- Легковесный Hybrid Decision Maker в экспериментальных прогонах (`Real Memory Replay`, Эксперимент №7) показал `Decision Accuracy = 80.0%` и критически важный `Abstention Rate = 40.0%` (способность сказать `UNCERTAIN` вместо слепого гадания).

### Не подтверждено / Ограничения:
- Точность 80% на ограниченном наборе трасс **недостаточна** для безусловного включения компонента в production. Требуется предварительная валидация в `shadow mode`.
- Масштабируемость алгоритмов принятия решений на миллионы реальных сессий в облачном окружении требует дополнительных замеров.

---

## 3. Границы ответственности Memory Decision Layer

`Memory Decision Layer` — это изолированный легковесный компонент, располагающийся строго между `Retrieval` и `Cognitive Context`.

### Что слой ДЕЛАЕТ:
1. Получает от `Retrieval` список кандидатов (`Top-K`).
2. Оценивает кандидатов относительно текущего хода и контекста.
3. Возвращает по каждому кандидату один из 5 вердиктов:
   - `KEEP` — кандидаты, допущенные в когнитивный контекст.
   - `OUTDATED` — устаревшие версии фактов (сохраняются для истории, но неактуальны).
   - `DISCARD` — семантические дистракторы и ложные воспоминания.
   - `CONFLICT` — факты, требующие разрешения версий.
   - `UNCERTAIN` — недостаточно данных для уверенного решения (безопасный отказ).

### Что слой КАТЕГОРИЧЕСКИ НЕ делает:
- **Не хранит память** (не заменяет персистентные хранилища).
- **Не управляет Workspace** и стейтом сессии.
- **Не управляет сессиями** и авторизацией.
- **Не вызывает LLM** для принятия решений (работает на детерминированных признаках и правилах).
- **Не становится новым Memory Manager** (не разрастается до монолитного сервиса).

---

## 4. Входные и выходные контракты

### Вход от Retrieval:
- Список сырых кандидатов памяти (`List[Dict[str, Any]]`), содержащих текст, метаданные, `timestamp`, флаг `is_stale`, и первичный скор релевантности.
- Текущий контекст хода (интент, активные цели, текущий фокус).

### Выход от Decision Layer:
- Отфильтрованный и ранжированный список кандидатов со статусами вердиктов, готовый для инжекции в `Cognitive Context`.

---

## 5. Используемые признаки (Features)

Для вынесения вердикта разрешается использовать исключительно следующие признаки:
1. **Semantic Relevance** (скор релевантности от Retrieval).
2. **Recency** (время создания / `timestamp`).
3. **Version / Temporal Validity** (признак актуальности версии, флаг `is_stale`).
4. **Conflict Status** (наличие противоречащих утверждений в пуле).
5. **Session Scope** (проверка принадлежности к текущей сессии).

---

## 6. Интеграция и Rollback

### Интеграция:
Слой внедряется как чисто функциональный вызов в пайплайне перед передачей контекста генератору:
```python
candidates = retrieval.search(query)
decisions = MemoryDecisionLayer.evaluate(candidates, context)
valid_memory_context = [d for d in decisions if d["verdict"] == "KEEP"]
```

### Rollback Plan:
При обнаружении аномалий или деградации ответов в production предусмотрен мгновенный откат (feature flag в конфигурации):
- При `ENABLE_MEMORY_DECISION_LAYER = false` пайплайн автоматически возвращается к поведению Baseline (передача сырого Top-K от Retrieval без промежуточной фильтрации).

---

## 7. Обязательные требования перед Production

Перед переводом слоя из режима `shadow mode` в `active production` обязательны:
1. Проведение расширенного валидационного теста на выборке из 100+ реальных replay-трасс.
2. Достижение порога `Decision Accuracy >= 92%` и минимизация ложных отсечений релевантных фактов.
3. Покрытие unit-тестами с проверкой поведения при появлении `UNCERTAIN`.
