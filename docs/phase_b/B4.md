# B4 — ContractValidator (контрактная валидация фаз)

## Цель
Добавить runtime-проверки: каждая фаза декларирует что требует на входе и что производит на выходе. Нарушения логируются (soft mode) или прерывают pipeline (strict mode).

## Архитектура

### `PhaseContract`
NamedTuple:
- `phase_name: str`
- `requires: set[str]` — ключи, которые ДОЛЖНЫ быть в контексте до фазы
- `produces: set[str]` — ключи, которые фаза ОБЯЗАНА произвести
- `optional_produces: set[str]` — ключи, которые фаза МОЖЕТ произвести

### `ContractValidator`
Методы:
- `register(contract: PhaseContract)` — регистрация контракта
- `pre_check(phase_name, ctx)` — проверяет `requires` (все ли ключи есть в context/секциях)
- `post_check(phase_name, ctx, before_keys)` — проверяет `produces` (появились ли ключи после фазы)
- `set_mode(mode)` — переключение `soft` (warning) ↔ `strict` (RuntimeError)

### Режимы
- **Soft** (текущий): логирует warning, pipeline продолжается
- **Strict**: `raise ContractViolationError` — pipeline прерывается

## Интеграция в executor.py

```python
# pipeline/executor.py — __init__
from .contracts import ContractValidator, PhaseContract

self.contract_validator = ContractValidator(mode="soft")
for contract in _BUILD_PHASE_CONTRACTS():
    self.contract_validator.register(contract)

# В execute() — перед каждой фазой:
self.contract_validator.pre_check(phase_name, ctx)

# После apply_phase_result:
self.contract_validator.post_check(phase_name, ctx, before_keys)
```
