# B3 — Устранение дублирования PipelineResult

## Цель
Сделать `PipelineResult` производным от typed-секций контекста, устранив два source of truth: `result` (куда фазы писали напрямую) и `context` (куда executor писал результат фазы).

## Проблема
До Phase B:
```python
# Фаза пишет:
result = PhaseResult(data={"response": "...", "confidence": 0.9})

# apply_phase_result пишет ВСЁ и в result, и в context:
self.result.response = data.get("response")
self.result.confidence = data.get("confidence")
ctx.context["response"] = data.get("response")
```
Два места, где хранятся одни и те же данные → риск рассинхронизации.

## Решение

### ResultBuilder (`_build_result`)
В `executor.py`:
```python
def _build_result(ctx, start_time) -> PipelineResult
```
- Берёт данные из typed-секций: `MemorySection` → `sources`, `StrategySection` → `response`, `confidence`, `intent_classification`, `EmotionSection` → `emotion_style`, `ImpulseSection` → `impulse_primary`, `ControlSection` → `safety_check`, `evaluation_feedback` и метаданные
- Вызывается в конце `execute()` перед запуском background-фаз и финализацией
- Результирующий `PipelineResult` — это всегда свежий срез секций

### Новый `_apply_phase_result`
Вместо прямой записи в `self.result`:
- Все writes идут в `ctx.control["<key>"]`
- Response-append (truth_loop disclaimer, evaluation feedback) перенаправлены в `ctx.strategy["response"]` через `ctx.update_context()`
- Сам `PipelineResult` не хранит state между фазами — только собирается в конце

### Anti-loop early return
Заменён `PipelineResult(...)` на `_build_result(ctx, start_time)` — даже при досрочном выходе результат консистентен.

### Safety block
Аналогично: `_build_result(ctx, start_time)` вместо `PipelineResult`.

## Что изменилось в executor.py

| Что | Было | Стало |
|-----|------|-------|
| apply_phase_result | пишет в `self.result.*` и `ctx.context["*"]` | пишет в `ctx.control["*"]`, append'ы в `ctx.strategy["response"]` |
| _build_result | — | **NEW** — собирает PipelineResult из секций |
| anti-loop return | `PipelineResult(...)` | `_build_result(ctx, start_time)` |
| safety return | `PipelineResult(...)` | `_build_result(ctx, start_time)` |
| result перед bg | прямые присвоения | `result = _build_result(ctx, start_time)` |

## Изменённые файлы
- `backend/core/pipeline/executor.py`: `_build_result()`, новый `_apply_phase_result`
