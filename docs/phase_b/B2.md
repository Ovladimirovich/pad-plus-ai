# B2 — Автогенерация bg_data

## Цель
Устранить ручную сборку `bg_data` в `executor.py`, заменив её автоматической сериализацией из typed-секций PipelineContext.

## Проблема
Ручная сборка `bg_data`:
```python
bg_data = dict(ctx.context)
bg_data["current_emotion"] = ...
bg_data["user_id"] = ...
# ... 11+ строк ручного копирования
```
- Хрупко: при добавлении новой секции легко забыть обновить сборку
- Дублирование логики: какие поля относятся к каким секциям — размазано по коду

## Решение

### `PipelineContext.to_background_snapshot()`
Единый метод, который:
1. Берёт все секции (memory, emotion, impulse, strategy, control)
2. Добавляет специальные поля (`user_id`, `dialog_id`, `current_emotion`, `current_mood`, `session_meta`)
3. Исключает ephemeral-ключи: `events`, `stream_queue`, `current_chunk`, `disclaimer_added`, `callback_data`, `broadcast_events`

### `_fire_background_phases`
```python
# Было: bg_data = {...} — 11 строк ручного dict
# Стало:
bg_data = ctx.to_background_snapshot()
```

### `_run_background_phase`
```python
# Было: распаковка каждого поля
user_id = bg_data.get("user_id")
dialog_id = bg_data.get("dialog_id")
# ... 8+ строк

# Стало:
phase_context = dict(bg_data)  # вся bg_data как context
```

## Изменённые файлы
- `backend/core/pipeline/context.py`: `to_background_snapshot()`
- `backend/core/pipeline/executor.py`: `_fire_background_phases`, `_run_background_phase`
