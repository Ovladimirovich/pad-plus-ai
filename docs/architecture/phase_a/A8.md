# A8: Handle `social_connection` — Wire Into Prompt or Remove

## Проблема

`EmotionState.social_connection` — поле в PADModel, которое **записывается** (при `user_praise`/`user_criticism` событиях), но **никогда не читается** в pipeline. GeneratePhase, EmotionPhase и другие фазы используют `emotion_style` (tone, verbosity, color), но не `social_connection`.

**Файл:** `backend/emotion/pad_model.py`, EmotionState:
```python
@dataclass
class EmotionState:
    pleasure: float = 0.0
    arousal: float = 0.0
    dominance: float = 0.0
    curiosity: float = 0.5
    confidence: float = 0.5
    social_connection: float = 0.0  # <-- This field
```

**Читатели:** `get_style()` не использует social_connection.

**Писатели:** `apply_event("user_praise")` — увеличивает, `apply_event("user_criticism")` — уменьшает.

## Причина

`social_connection` был добавлен как расширение PAD-модели, но ни один потребитель не был обновлён для его использования.

## Решение

### Вариант A: Встроить в `get_style()`

Использовать `social_connection` для модификации тона:

```python
def get_style(self) -> Dict[str, str]:
    ...
    # Социальная связь влияет на тон
    if self.social_connection > 0.3:
        tone = "warm"  # вместо "friendly"
    elif self.social_connection < -0.3:
        tone = "distant"
    ...
```

### Вариант B: Добавить в prompt generation

Передавать `social_connection` в GeneratePhase через `emotion_style`:

```python
# В EmotionPhase:
data["emotion_style"]["social_connection"] = str(round(emotion.social_connection, 2))
```

### Вариант C (рекомендуемый, ИМПЛЕМЕНТИРОВАН): Удалить из EmotionState

Если social_connection не нужен в ближайших планах — удалить поле. Можно добавить позже, когда появится реальный потребитель.

**В рамках Phase A реализован Option C:**
- `social_connection` удалён из `EmotionState` dataclass (поле, `to_dict`, нормализация, `load`/`save`)
- Удалён параметр `social_connection` из `update()` метода
- Удалены правила `apply_event` для `user_praise`/`user_criticism`
- Обновлены документационные ссылки в `persona_routes.py`

## Тест

**Новый тест для Варианта A или B:**

```python
async def test_social_connection_affects_style():
    state = EmotionState(pleasure=0.5, arousal=0.3, dominance=0.2, 
                         social_connection=0.8)
    style = state.get_style()
    # Если social_connection > 0.3, tone должен быть "warm"
    assert style["tone"] in ("warm", "friendly", "neutral")
```

**Новый тест для Варианта C:**

```python
async def test_social_connection_removed():
    state = EmotionState(pleasure=0.5, arousal=0.3, dominance=0.2)
    # Проверяем, что social_connection не вызывает ошибку при отсутствии
    assert not hasattr(state, 'social_connection') or state.social_connection == 0.0
    style = state.get_style()
    assert "tone" in style  # Базовая функциональность не нарушена
```

## Результат

| Вариант | Результат |
|---------|-----------|
| A (в style) | Social_connection влияет на тон ответа |
| B (в prompt) | LLM получает информацию о социальной связи |
| C (удалить) | Чище модель, меньше обязательств по поддержке |
