# A4: Register MemoryMaintenancePhase in Pipeline

## Проблема

`MemoryMaintenancePhase` (`backend/core/pipeline/phases/memory_maintenance.py`) — полностью реализованная фаза с логикой fusion и forgetting, но она **никогда не импортируется** в `__init__.py`, **не регистрируется** через `@register_phase` и **не инстанциируется** в executor.

## Причина

Фаза была написана, но забыта при рефакторинге pipeline v5.0. В `__init__.py` нет импорта `MemoryMaintenancePhase`.

## Решение

### Шаг 1: Добавить `@register_phase` декоратор

В `memory_maintenance.py` добавлен импорт и декоратор:

```python
from ..registry import register_phase

@register_phase("memory_maintenance", order=19)
class MemoryMaintenancePhase(PipelinePhase):
    name = "memory_maintenance"
    ...
```

`order=19` ставит фазу в foreground (hot path) между `impulse_update` (order=18) и `events_broadcast` (order=20). Это было осознанным решением: fusion/forgetting дешевле исполнять синхронно, чем плодить background-задачи.

### Шаг 2: Импортировать в `__init__.py`

В `backend/core/pipeline/phases/__init__.py` добавлено:

```python
from .memory_maintenance import MemoryMaintenancePhase
```

И в `__all__`:
```python
"MemoryMaintenancePhase",
```

### Отклонённая альтернатива: background phase

Оригинальный план предлагал добавить `memory_maintenance` в `_BACKGROUND_PHASES`. Это было отклонено, потому что:
- Fusion/forgetting — лёгкая операция (O(n) по количеству items)
- Foreground исполнение гарантирует выполнение до завершения pipeline
- Background-фазы могут быть пропущены при shutdown

## Тест

**Существующий тест:** `tests/test_pipeline/test_orchestrator.py`
- Проверить, что pipeline создаёт фазу `memory_maintenance`

## Результат

| До | После |
|----|-------|
| Fusion/forgetting логика существует, но никогда не запускается | Логика выполняется в каждом pipeline цикле (foreground, order=19) |
| Мёртвый код (~100 строк) | Работающий механизм очистки памяти |
| Память растёт монолитно | Дубликаты сливаются, устаревшее забывается |
