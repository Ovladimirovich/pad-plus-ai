# A9: Clean Up Written-But-Never-Read ctx Keys

## Проблема

EmotionUpdatePhase пишет в `ctx.context` ключи `emotion_event` и `emotion_intensity`, но **ни одна фаза** их не читает. Это загрязняет namespace контекста pipeline и вводит в заблуждение при отладке.

**Файл:** `backend/core/pipeline/phases/emotion_update.py`:
```python
# Эти ключи пишутся, но никем не читаются:
"emotion_event": emotion_event,
"emotion_intensity": emotion_intensity,
```

## Причина

`emotion_event` и `emotion_intensity` были добавлены как метаданные для гипотетического потребителя (возможно, для event bus или external logging), который так и не был реализован. Остальные ключи, записываемые EmotionUpdatePhase (`emotion_state`, `emotion_style`, `pad_vector`, `emotional_shift`), активно читаются GeneratePhase и другими фазами.

## Решение

Удалены `emotion_event` и `emotion_intensity` из `PhaseResult.data` в `emotion_update.py`.

**До:**
```python
return PhaseResult(
    success=True,
    data={
        "emotion_state": normalized,
        "emotion_style": style,
        "pad_vector": pad_vector,
        "emotional_shift": shift,
        "emotion_event": emotion_event,        # 🗑️ never read
        "emotion_intensity": emotion_intensity, # 🗑️ never read
    },
)
```

**После:**
```python
return PhaseResult(
    success=True,
    data={
        "emotion_state": normalized,
        "emotion_style": style,
        "pad_vector": pad_vector,
        "emotional_shift": shift,
    },
)
```

### Анализ других потенциально мёртвых ключей

В рамках A9 были проверены все ключи, записываемые в `ctx.context`, на предмет чтения. Следующие ключи пишутся, но **не являются мёртвыми** — они используются как метаданные для ResultBuilder в executor.py или передаются во внешние системы:

| Ключ | Записывается | Использование |
|------|-------------|---------------|
| `response` | generate_phase | Читается evaluation_phase, save_episode, truth_loop |
| `intent` | intent_phase | Читается rag_phase, generate_phase |
| `truth_confidence` | generate_phase | Читается save_episode |
| `emotion_state` | emotion_update | Читается generate_phase |
| `emotion_style` | emotion_update | Читается generate_phase |
| `pad_vector` | emotion_update | Читается generate_phase |
| `emotional_shift` | emotion_update | Используется в response_guard |
| `procedure_name` | semantic_phase | Читается save_episode (см. A2) |
| `result_dict` | executor (A3) | Читается reflection_phase |
| `execution_time_ms` | executor (A1) | Читается evaluation_phase |

Только `emotion_event` и `emotion_intensity` были подтверждены как никогда не читаемые.

| До | После |
|----|-------|
| `ctx.context` содержит `emotion_event` и `emotion_intensity` (никем не читаемые) | Чистый ctx, только реально используемые ключи |

| Вводят в заблуждение при отладке | Отладка показывает только релевантные данные |
