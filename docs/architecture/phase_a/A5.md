# A5: Fix MemoryHygiene — Remove Simulated Deletions, Keep Diagnostics

## Проблема

`MemoryHygiene.run_cleanup()` **симулирует** очистку. Все подсчёты — `duplicates_found`, `obsolete_found`, `low_quality_found` — вычисляются как доля от `items_scanned`, но никаких реальных удалений не производится.

**Файл:** `backend/memory/hygiene.py`, строки ~165-230

```python
# Анализируем дубликаты (симуляция)
report.duplicates_found = max(0, report.items_scanned // 20)
if not dry_run:
    report.duplicates_removed = report.duplicates_found // 2
```

## Причина

`run_cleanup()` не имеет доступа к реальным данным памяти. Он собирает только `stats` (метаданные), а не сами записи. Поэтому реальное удаление невозможно — метод оперирует статистикой, а не объектами.

## Решение

### Выбранный вариант: Option B (убрать симуляцию, оставить диагностику)

Изменены подсчёты `_removed` полей с симулированных (`items_scanned // 20`) на честные `0`. Добавлен комментарий: «Диагностика — только метрики, без симуляции удаления».

```python
# Реальные удаления выполняются в MemoryMaintenancePhase (order=19)
self.duplicates_removed = 0
self.obsolete_removed = 0
self.low_quality_removed = 0
```

### Почему не Option A (интеграция с MemoryModules)

Option A был отклонён в рамках Phase A, потому что:
- Он требует изменений API нескольких модулей памяти (scope creep)
- Phase A запрещает новые фичи — только фикс дефектов и удаление мёртвого кода
- Реальный cleanup уже существует: `MemoryMaintenancePhase` (A4) выполняет fusion/forgetting с реальными данными

### Где происходит реальная очистка

`MemoryMaintenancePhase` (foreground, order=19) в `phases/memory_maintenance.py`:
- Загружает MemoryItem из кэша фазы
- Выполняет `find_duplicates()` и `find_obsolete()` на реальных данных
- Удаляет через фабрику памяти при `dry_run=False`

## Тест

**Существующий тест:** `tests/test_hygiene.py` — 1 тест проходит: проверяет, что `run_cleanup()` не падает и возвращает `HygieneReport`.

## Результат

| До | После |
|----|-------|
| `run_cleanup()` симулирует удаление (`items_scanned // 20`) | `run_cleanup()` возвращает честные `0` для `_removed` полей |
| `duplicates_removed = items_scanned // 40` (ложные цифры) | `duplicates_removed = 0` (честная диагностика) |
| Двойная ответственность: и диагностика, и симуляция | Одно назначение: сбор метрик |
| Реальный cleanup отсутствовал | Реальный cleanup выполняется в MemoryMaintenancePhase (A4) |
