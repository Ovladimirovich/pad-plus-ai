# A6: Remove `PersonaMemory.users` — Single Source of Truth for Per-User State

## Проблема

**CRITICAL.** `PersonaMemory` (глобальный синглтон) хранит `users: Dict[str, InteractionMemory]` — per-user данные о взаимодействиях. Параллельно `UserPersona` (per-user, управляется `UserPersonaManager`) хранит ту же информацию. Оба пути записи независимы и не синхронизированы.

**Файл:** `backend/memory/persona.py`, строка ~175:
```python
self.users: Dict[str, InteractionMemory] = {}
```

**Файл:** `backend/memory/persona.py`, `record_interaction()` — пишет в `self.users`.

**Файл:** `backend/memory/user_persona.py`, `UserPersona.record_interaction()` — пишет в `UserPersona`.

## Причина

Исторически `PersonaMemory` был единственным хранилищем. Когда появился `UserPersonaManager`, старый код не был удалён. `PersonaPhase` (pipeline) вызывает **оба**:

```python
# persona.py — line ~38:
persona.record_interaction(...)
# user_persona.py — вызывается из persona_evolution.py
user_persona.record_interaction(...)
```

## Решение

### Шаг 1: Удалить `PersonaMemory.users`

Убрать поле `users` и все методы, которые его читают/пишут:

```python
# Удалить:
self.users: Dict[str, InteractionMemory] = {}

# Удалить:
def record_interaction(self, user_id, topic=None, emotion="neutral"):
    ...

def get_user_memory(self, user_id):
    ...
```

### Шаг 2: Обновить `_to_dict()` и `_from_dict()`

Убрать сериализацию `users`:

```python
def _to_dict(self) -> dict:
    return {
        ...
        # Убрать: "users": {k: u.to_dict() for k, u in self.users.items()},
        ...
    }

def _from_dict(self, data: dict) -> None:
    ...
    # Убрать: self.users = {...}
    ...
```

### Шаг 3: Обновить вызовы

Проверить, что никто не вызывает `persona.record_interaction()`:

- `backend/core/pipeline/phases/persona.py` — вызывает `user_persona.record_interaction()`, но НЕ вызывает `persona.record_interaction()`. ✅
- `backend/memory/persona.py` — `evolve_from_dialog()` вызывает `adjust_trait()`, но не `record_interaction()`. ✅
- API routes — проверить, нет ли вызовов `persona.record_interaction()`.

### Шаг 4: Удалить `InteractionMemory` класс

Dataclass `InteractionMemory` используется только `PersonaMemory.users`. После удаления можно удалить и класс.

## Тест

**Существующий тест:** `tests/test_pipeline/test_persona.py`
- Проверить, что pipeline не падает после удаления `PersonaMemory.users`

**Новый тест:** Проверка single source of truth:

```python
async def test_per_user_data_only_in_user_persona():
    # Проверяем, что PersonaMemory больше не содержит per-user данные
    persona = get_persona()
    assert not hasattr(persona, 'users') or persona.users == {}
    
    # Проверяем, что UserPersonaManager содержит данные
    manager = get_user_persona_manager()
    up = manager.get_persona("test_user")
    up.record_interaction(topic="AI")
    assert up.total_interactions == 1
    
    # Пересоздаём PersonaMemory и проверяем, что данных нет
    persona2 = get_persona()
    if hasattr(persona2, 'users'):
        assert "test_user" not in persona2.users
```

## Результат

| До | После |
|----|-------|
| Два независимых пути записи per-user данных | Один путь: `UserPersona` |
| `PersonaMemory.users` и `UserPersona` могут расходиться | Single source of truth |
| 100+ строк мёртвого кода | Код удалён, интерфейс чище |
| Каждый pipeline цикл пишет в два места | Pipeline пишет только в `UserPersona` |
